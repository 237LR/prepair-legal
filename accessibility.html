Accessibility Statement

Last Updated: October 17, 2025

Our Commitment to Accessibility

Prepair is committed to ensuring digital accessibility for people with disabilities. We are continually improving the user experience for everyone and applying the relevant accessibility standards to ensure we provide equal access to all of our users.

1. Conformance Status

We strive to conform to the following accessibility standards:

  • WCAG 2.1: Web Content Accessibility Guidelines (WCAG) 2.1 Level AA
  • iOS Accessibility: Apple's Human Interface Guidelines for Accessibility
  • Section 508: U.S. Section 508 Standards
  • EN 301 549: European accessibility standard for ICT products and services

2. Accessibility Features

2.1 iOS Native Accessibility Support

Prepair is built using native iOS frameworks and supports the following iOS accessibility features:

VoiceOver Support

  • Full VoiceOver compatibility for screen reader users
  • Descriptive labels for all interactive elements
  • Proper heading hierarchy and navigation landmarks
  • Meaningful accessibility hints for complex interactions

Dynamic Type

  • Support for iOS Dynamic Type allowing text size customization
  • Text scales appropriately based on user preferences
  • Layout adapts to larger text sizes without losing functionality

High Contrast and Display Accommodations

  • Support for iOS Increase Contrast mode
  • Compatibility with Smart Invert Colors and Classic Invert
  • Respect for Reduce Transparency settings
  • Support for Dark Mode and Light Mode preferences

Motion and Animation

  • Respect for Reduce Motion settings
  • Alternative presentations for animated content when motion is reduced
  • No auto-playing videos or animations that cannot be paused

Audio and Speech

  • Compatibility with hearing devices and audio routing
  • Visual alternatives for all audio content
  • Adjustable audio levels and voice settings
  • Support for mono audio when needed

2.2 Keyboard and Switch Control

  • Full keyboard navigation support (for external keyboards)
  • Switch Control compatibility for users with motor disabilities
  • Logical tab order and focus management
  • Visible focus indicators

2.3 Color and Contrast

  • Minimum contrast ratio of 4.5:1 for normal text
  • Minimum contrast ratio of 3:1 for large text and UI components
  • Information not conveyed by color alone
  • Colorblind-friendly color palettes

2.4 Interview Practice Accessibility

  • Text-Based Mode: Fully accessible text-based interview practice for users who cannot or prefer not to use audio/video
  • Audio Descriptions: Clear audio prompts with text alternatives
  • Flexible Timing: No strict time limits; users can practice at their own pace
  • Pause and Resume: Ability to pause interviews and return later
  • Alternative Input: Support for voice input, keyboard input, and touch input

3. Known Limitations

We are aware of the following accessibility limitations and are actively working to address them:

3.1 Video Interview Mode

  • Limited for Blind Users: Video interview mode is primarily visual and may not be fully accessible to blind users. We recommend using our audio-only or text-based interview modes as alternatives.
  • Workaround: All interview content is available in accessible text-based formats

3.2 Speech Recognition

  • Accuracy Variations: Speech-to-text accuracy may vary for users with speech disabilities or non-standard speech patterns
  • Workaround: Text input is available as an alternative to voice input in all interview modes

3.3 Third-Party Content

  • AI-Generated Content: Some AI-generated interview questions may not be optimally formatted for screen readers
  • Status: We are working with our AI providers to improve content accessibility

4. Assistive Technologies

Prepair has been tested with the following assistive technologies:

  • VoiceOver: iOS built-in screen reader (iOS 15 and later)
  • Voice Control: iOS voice control navigation
  • Switch Control: iOS switch-based navigation
  • Magnifier: iOS screen magnification
  • Dictation: Voice-to-text input

5. Testing and Evaluation

We employ the following methods to ensure accessibility:

  • Automated accessibility testing using Xcode Accessibility Inspector
  • Manual testing with VoiceOver and other assistive technologies
  • Regular audits against WCAG 2.1 AA standards
  • User testing with individuals who use assistive technologies
  • Continuous monitoring and improvement based on user feedback
